## 兼容改动为何必要

`source/shared/mods.js` 维护具名干员、盟约和策略目录与组合规则。
`source/shared/native-settings.js` 负责转换宿主设置：普通选项保留清楚的键名，数量较多的成员选择使用三个整数
保存，界面仍显示逐项选择。目前共 29 项设置，没有提高宿主的 32 项限制。成员目录顺序属于保存格式，后续新增应追加到末尾。
旧的逐成员设置仍可通过转换函数读入；旧运行中房间不作为升级恢复对象。

发布包没有六名自定义干员的自选身体。`build-diy.mjs` 从作者普通／精锐棋子生成这些身体，保持作者的面板和技能，
使用原有自选组合器和 V／VI 阶槽位，不引入另一套自选实现。原型通过既有锁定选择保留自身驻防。

宿主只补充了装备单件授予盟约的共有读取，以及原型驻防传递。前者在整备计数、战斗成员、卡片显示中一致；
自身所属盟约的驻防叠层不因为佩戴人格羁绊而额外增加对象。宿主的普通盟约、装备配对、确定性时钟和网络协议不变。

作者仍带有此前已修复的阿米娅治疗、结城理替身与弱点伤害、罗德岛溢出攻击问题。本次保留这些修复；
罗德岛同帧攻击前会重新钳制上限，避免技能或其他攻击 buff 到期后在该帧超出上限。
大型黑板阈值在构建时按百为单位保存，在对应运行时读取点还原，继续服从原有插件校验。

发布包未包含 `mod-content.mjs` 生成器，因此保留其提供的数据快照作为构建输入，沿用已有适配方式。
不要手改顶层 `data/*.json` 或插件 bundle；修改源模块／构建器后重建。
`import-author.mjs` 仅用于导入新作者版本，导入后需核对并迁移本地兼容修复；日常重建无需再次下载或导入。
导入后可用 `prepare-author-audio.mjs <官方 audio_data.json>` 生成离线音库补充。原作者自定义音效没有官方音库元数据时，
采用已有无音库播放路径的默认值：同池上限 2、不抢占、音高 1、无延迟（[ASSUMED]）；不伪造官方参数。
新增人格面具角色只提供日语语音，保留作者原始语种；最终为 990 项音效引用、960 个音库。

```text
node mods/marisa-native/build-runtime.mjs
node mods/marisa-native/build-ui.mjs
node mods/marisa-native/build-tests.mjs
node mods/marisa-native/prepare-assets.mjs
node tools/plugin.mjs pack marisa
node tools/plugin.mjs check marisa --strict
```

安装目录 `plugins/marisa/` 应与可提交的 `mods/marisa-native/bundle/marisa/` 同步。
Windows 双击仓库根目录的 `启动魔理沙MOD.cmd`，或工程内的 `scripts/start-windows.bat` / `scripts/start-marisa.cmd`。
这些入口会在首次启动时将源码自带的 bundle 安装到 `plugins/marisa/`，并开启 sandbox 脚本支持。
游玩启动沿用已准备的素材，不运行官方素材清单重建；源码首次使用仍需先准备游戏素材。
未手动指定 `SP_SCRIPT_PROBE_MS` 时，使用 20 秒初始化检查限时，避免 Windows 上较大的 MOD 被默认 5 秒限时误停用。
创建房间与应用插件设置的页面请求等待 45 秒，覆盖冷启动时的内容组合和脚本检查；其他请求仍使用原有超时。
没有本机策略文件时创建 `plugins/config.json`，使新房间默认启用 `marisa`；已有插件文件与策略不覆盖。
在「选择模拟协议」界面（建房之前）可通过标题下的插件管理器检查、调整 MOD，选择会随创建的房间一起生效；进房后同一位置的标签只显示结果。已运行的服务需要先关闭启动窗口再重启，旧房间需重建。
